# 读书与评书模块开发计划

状态：已确认产品方向，尚未实施。

## 1. 目标与范围

建设独立的读书与评书模块，包含公共书目、用户提交的书目资料、私有电子书导入、站内阅读、阅读进度、评分、短书评、长书评关联和书籍讨论。

本计划首期覆盖 `Atoman-Backend` 与 `Atoman-Frontend`。当前工作区未包含 iOS 客户端；新增 API、数据模型和权限语义需要保留后续移动端接入空间。

本计划不把书籍实现为博客文章，也不将公共书目直接建模为 `ContentEntry`。书籍是资料库实体；长书评才使用博客发布能力。

## 2. 已确认的产品决策

- 公共书目与电子书正文分离。书目公开不等于正文可阅读。
- 用户可以上传电子书正文；首期接受 EPUB、PDF 和 TXT。
- 电子书正文默认私有，仅上传者可查看、阅读和全文检索。
- 私有正文关联公共书目后，权限不会自动升级为公开。
- 公共正文必须由用户明确申请发布，并提交资料来源和授权声明；审核通过后才可访问。
- 首期不接受 MOBI/AZW、Office 文档、压缩包或任意可执行格式。
- 用户可提交公共书目、版本资料和修订，采用 Music 的提交、审核、修订与合并机制。
- 公共书目资料必须至少提供一条资料来源。
- 短书评默认公开，允许作者设为仅自己可见；短书评公开不会披露作者是否拥有私有正文文件。
- 评分采用 5 分整数制，每位用户对每部公共作品最多保留一条评分。
- 长书评使用 Blog 文章，并通过书籍关联展示在书籍详情页；不在首期新增 `ContentEntry.kind = book_review`。
- 书籍详情页的讨论接入现有统一评论核心；书目讨论与结构化短书评分开。
- 首批测试文件只使用自行生成、开源或公版文本，且默认不进入公共资源库。

## 3. 非目标

首期不包含以下能力：

- 自动将用户上传的电子书公开给其他用户。
- 电子书商店、付费购买、DRM、借阅、订阅付费或版权交易。
- 未经授权的受版权保护文本分发。
- MOBI/AZW、DOC/DOCX、扫描 OCR、压缩包导入和任意格式转换。
- 跨书籍的全文公开搜索或从私有文本训练推荐模型。
- 将私有阅读历史、私有笔记或私有文件暴露到 Feed、搜索、推荐或公开个人主页。
- 书评回复线程；首期只提供书籍页统一讨论线程。
- iOS 客户端实现。

## 4. 领域模型

### 4.1 公共书目

| 实体 | 责任 | 关键关系 |
| --- | --- | --- |
| `BookWork` | 规范作品，如同一小说的抽象作品层 | 可有多个 `BookEdition`；作为评分、书评和讨论目标 |
| `BookEdition` | 具体版本，包括出版社、ISBN、译者、页数、装帧与封面 | 属于一个 `BookWork`；可有公共可读资源 |
| `BookPerson` | 作者、译者、编者、绘者等人物资料 | 通过贡献关系关联作品或版本 |
| `BookContribution` | 人物与作品/版本的角色关系 | 角色包括作者、译者、编者、绘者、校对等 |
| `BookSource` | 书目、版本或封面的可核验资料来源 | 至少有一条来源才能提交公共书目 |
| `BookEdit` | 新建、修订、合并、下架等公共书目申请 | 记录提交人、载荷、变更、来源、理由、审核决定 |

`BookWork` 与 `BookEdition` 使用独立的生命周期和编辑状态，参考 Music 的 `draft / active / retired / merged` 与 `development / locked / closed` 语义。书籍作者和译者不得复用 Music 的 `Artist` 实体。

### 4.2 私有导入与阅读

| 实体 | 责任 | 可见性 |
| --- | --- | --- |
| `UserBookImport` | 用户导入会话、私有元数据、解析状态和关联的公共版本 | 仅上传者 |
| `UserBookAsset` | 上传源文件、检测结果、哈希、对象键和派生阅读资源 | 仅上传者 |
| `UserBookReadingState` | EPUB CFI、PDF 页码、阅读百分比、最后阅读时间与私有笔记 | 仅上传者 |
| `UserBookShelf` | 想读、在读、读过、搁置、弃读等作品层阅读状态 | 默认仅上传者，可在后续单独增加公开设置 |

私有导入不直接创建公共 `BookWork`。用户可在导入后匹配已有公共作品或版本；若未找到，可单独提交公共书目申请。私有标题、作者、封面、阅读位置、正文和笔记均不得由公共书目接口返回。

### 4.3 公共正文与互动

| 实体 | 责任 | 访问规则 |
| --- | --- | --- |
| `BookPublicationRequest` | 将私有资源申请为公共资源 | 提交者、审核者可访问申请信息 |
| `BookRightsDeclaration` | 授权类型、权利人、来源、证明与审核结论 | 仅提交者、审核者和审计人员 |
| `PublishedBookAsset` | 审核通过后独立创建的公共或受限阅读资源 | 仅按审核后的访问范围读取 |
| `BookRating` | 用户对公共作品的 1 至 5 分评分 | 每用户每作品唯一 |
| `BookReview` | 用户对公共作品的短书评、剧透标记和可见性 | 公开或仅作者本人 |
| `BookPostLink` | Blog 文章与公共作品的关联 | 可一篇文章关联多部书，一部书关联多篇文章 |

不得通过修改 `UserBookAsset` 的可见性把私有文件转为公共文件。公共申请审核通过后，创建独立的 `PublishedBookAsset`，并保留来源、审核和撤销记录。

## 5. 权限与隐私边界

### 5.1 私有电子书

- 只有上传者可以列出、读取、预览、下载或全文搜索自己的私有资源。
- 私有资源不进入全站搜索、推荐、Feed、公开书目详情、用户公开主页或其他用户的书架。
- 管理员不默认浏览私有正文。只有用户提交公共资源申请后的指定资源，才对具有审核权限的人员开放审查。
- 原始文件和派生资源必须使用用户隔离的对象存储前缀；所有读取经服务端授权并返回短时签名 URL。
- 用户删除导入后立即撤销读取权限，并异步删除原文件、派生资源、阅读位置和私有全文索引。
- 阅读进度、笔记和私有书架不作为公共推荐信号，也不参与跨用户统计。

### 5.2 公共书目与用户贡献

- 登录用户可在具备 `books.submit` 能力时提交新书目、版本、修订和合并建议。
- 具备 `books.review` 能力的审核者可以审核书目、版本、合并、下架和公开资源申请。
- 审核者不得审核自己提交的申请。
- `BookWork` 或 `BookEdition` 合并时，旧链接保留重定向；评分、书评、书架关联和文章关联迁移至规范对象。
- 作品关闭、下架或合并后，不再接受新评分、书评或讨论，但保留审计与重定向语义。

### 5.3 评分、书评与讨论

- `BookRating` 只关联已发布的 `BookWork`，评分范围是 1 至 5 的整数。
- `BookReview` 每位用户对每部作品最多一篇；作者可修改、删除或设为仅自己可见。
- 书评默认公开，但书评可见性不影响用户的私有导入和书架可见性。
- 书籍详情页讨论通过评论核心的 `book_work` 目标类型实现。评论目标解析必须拒绝未发布、合并或关闭的资源。
- 长书评仍是博客文章，遵守文章自身的频道、可见性、发布、版本和评论规则。

## 6. 文件上传与处理流程

### 6.1 私有导入流程

```text
创建导入会话
-> 申请分片上传地址
-> 上传文件并完成会话
-> 文件扫描和格式识别
-> 元数据提取与阅读资源生成
-> 私人阅读和进度保存
```

上传会话、分片传输、失败恢复和异步任务可参考 Music 的实现模式；书籍模块使用独立的数据表、对象前缀和处理队列，不复用音频转码或播放对象权限。

### 6.2 安全处理要求

- 同时校验 MIME 类型、文件魔数和文件扩展名，不相信客户端声明。
- 执行大小、页数、章节数、解压比和处理时长限制。
- 为每个文件计算 SHA-256，支持同一用户的重复文件识别，但不得借此泄露其他用户是否上传过同一文件。
- 对文件执行病毒扫描与隔离；扫描失败、格式不符或解析超时不得生成可读资源。
- EPUB 作为不可信 ZIP 处理：限制条目数量、总解压大小和解压比，拒绝路径穿越、绝对路径、符号链接和外部资源自动抓取。
- PDF 不执行嵌入脚本、不自动请求外部资源；渲染或预览位于隔离上下文中。
- TXT 在服务端规范化为 UTF-8，拒绝无法安全解码的内容。
- 原始资源默认不公开。读取和下载均使用短时授权，不生成可猜测的永久公开路径。

### 6.3 文件状态机

```text
pending_upload -> uploading -> uploaded -> scanning -> metadata_ready
                                                    -> failed

metadata_ready -> private_available
metadata_ready -> publication_requested -> pending_review -> published
                                                   -> rejected
                                                   -> quarantined
                                                   -> removed
```

书目状态与文件状态相互独立。公共书目可以没有可读正文；某一版本可有多个不同许可和格式的公共资源；私有资源不会因为书目状态改变而改变可见性。

## 7. 公共正文发布与版权治理

用户将私有资源申请公开时，必须显式选择授权类型并提供对应证明。首期允许的类型为：

- `public_domain`：公版作品。
- `open_license`：兼容的开放许可。
- `creator_owned`：上传者拥有可分发的版权。
- `authorized_distribution`：具有明确书面授权。

申请内容包括关联书目或版本、文件哈希、资料来源、授权说明、权利人信息和证明资源。审核通过后创建独立公共资源；拒绝、隔离或下架的资源不能作为公共阅读入口。

公共资源支持被举报、下架和恢复。下架应立即撤销公开访问；书目、评分和书评是否保留取决于书目本身状态，不由文件下架直接决定。

## 8. API 契约与模块接入

### 8.1 Backend

在 `internal/modules/books` 新增独立模块，并在应用路由注册 `/api/v1/books`。API 必须同步更新 Swagger 和项目接口文档。

首期 API 分组：

- 公共书目：作品搜索、作品详情、版本详情、人物详情、作品评分、短书评、相关文章和讨论。
- 私人书库：创建导入会话、分片上传、完成或取消导入、列出我的导入、删除导入、读取授权、阅读位置保存、私有书架管理和私有全文搜索。
- 贡献流程：提交作品或版本、提交修订、列出本人申请、撤回申请、提交合并建议。
- 审核流程：书目申请、修订、合并和公开资源申请的列表、详情、通过、驳回、隔离、下架和恢复。
- 公共正文：仅对审核通过的资源提供受限读取和阅读元数据接口。

所有资源查询都必须在服务层验证所有权、书目生命周期、文件状态和授权范围。HTTP handler 不得自行拼接对象存储路径或绕过服务层授权。

### 8.2 Frontend

新增 `books` 模块房间、导航顺序、站点开关、模块路由和 API 类型。路由只表达读书空间内的位置，建议为：

```text
/books
/books/search
/books/work/:workId
/books/edition/:editionId
/books/library
/books/import/:importId
/books/read/:assetId
/books/contributions
/books/review
```

新增能力开关：

- `books.submit`：提交公共书目和修订。
- `books.review`：审核书目、版本、合并和公开资源申请。
- `books.publish_asset`：申请将私有正文发布为公共资源。

主要用户界面：

- 公共书目发现、搜索、作品详情、版本详情、评分、短书评、相关文章和讨论。
- 我的书库、导入列表、文件处理状态、阅读状态、私有笔记和文件删除。
- 多步骤导入界面：查重、填写私有元数据、上传、解析结果、关联已有书目或提交书目申请。
- 阅读器：目录、进度、继续阅读、访问受限、文件处理失败和删除状态。
- 贡献中心：我的书目申请、修订、合并建议、公共资源申请和审核结果。
- 审核台：待审书目、版本、合并、授权材料和公共资源状态。

EPUB 使用成熟的阅读器库并保存 CFI 位置；PDF 使用成熟 PDF 阅读组件并保存页码和缩放偏好；TXT 使用受控的章节或分页视图。不得自行实现 EPUB 解析或 PDF 渲染引擎。

## 9. 实施顺序

### 迭代 0：契约与基础模型

1. 冻结 API 资源、状态机、错误码、对象可见性和权限表。
2. 新增书目、私有导入、资源授权、评分、书评和关联文章的数据模型、迁移和索引。
3. 注册 books 模块、站点开关、Frontend 模块房间和空路由骨架。
4. 建立公共与私有资源隔离的统一授权函数。
5. 更新 API 文档和模块设计说明。

验收：私有资源与公共书目从模型和查询入口上分离；没有任何默认公开的正文读取路径。

### 迭代 1：私有导入与文件安全

1. 实现导入会话、分片上传、取消、失败恢复和用户配额。
2. 实现格式识别、病毒扫描、哈希、EPUB/PDF/TXT 安全检查和异步处理状态。
3. 实现私有对象存储、读取授权、删除撤权和异步清理。
4. 实现私有导入列表、处理状态和删除界面。

验收：用户不能读取其他用户的原文件、派生资源或私有全文索引；失败和删除文件不会保留有效读取链接。

### 迭代 2：私人阅读与阅读状态

1. 集成 EPUB、PDF 和 TXT 阅读体验。
2. 保存和恢复 EPUB CFI、PDF 页码、百分比、最后阅读时间和私有笔记。
3. 提供书库筛选、继续阅读和导入与公共书目关联。
4. 验证阅读状态在不同设备和刷新后的恢复行为。

验收：阅读进度只对本人可见，且不会进入公开搜索、Feed 或推荐。

### 迭代 3：公共书目与社区贡献

1. 实现作品、版本、人物、贡献关系、资料来源、编辑记录、投票、审核与审计。
2. 强制提交来源，实施自审拦截、修订状态、关闭、重开和合并状态机。
3. 实现公共书目搜索与详情，采用公开书目字段建立索引。
4. 实现合并时的重定向和关联迁移。

验收：普通用户只能操作自己的申请；审核者不能审核自己提交的申请；合并后旧链接和已有互动均保持一致语义。

### 迭代 4：评分、书评、文章关联与讨论

1. 实现 1 至 5 分评分、聚合统计与每用户每作品唯一约束。
2. 实现短书评、剧透标记、公开/私有可见性和作者编辑删除。
3. 实现 Blog 文章与书籍的多对多关联，并在双方详情页展示。
4. 为 `book_work` 注册统一评论目标与可见性解析。

验收：仅公开作品可评分、公开书评和评论；私有资源、私有书架和私有短评不泄露到作品详情页。

### 迭代 5：公共正文发布与治理

1. 实现公开资源申请、授权声明、证据上传、审核、拒绝、隔离、下架和恢复。
2. 审核通过时创建独立 `PublishedBookAsset`，不更改原私有资产的权限。
3. 实现公共资源阅读入口、公开资源访问控制和侵权举报/下架流程。
4. 补充授权类型、文件状态、下架、恢复和审计记录的界面与 API 文档。

验收：没有已批准授权的资源永远不能经公共书目读取；资源下架立即撤销公共读取权限。

## 10. 测试与验证

### 10.1 Backend

覆盖以下场景：

- 数据模型约束、状态转换、迁移和索引。
- 私有对象所有权、签名读取链接、缓存控制和删除撤权。
- 分片上传的重试、取消、过期会话和失败清理。
- EPUB 路径穿越、压缩炸弹、伪造 MIME、超大 PDF、异常编码 TXT 和扫描失败。
- 用户间资源隔离、审核者不可访问未提交私有资源、审核者不可自审。
- 书目修订、合并、旧链接重定向和互动关联迁移。
- 评分唯一性、书评可见性、关闭作品的互动拒绝和评论目标解析。
- 公共资源授权、下架、恢复、资源访问和举报状态。

完成每个 Backend 迭代后至少运行相关测试、`gofmt` 和：

```bash
cd Atoman-Backend
go build ./...
```

### 10.2 Frontend

覆盖以下场景：

- 模块导航、路由守卫和能力开关。
- 私有书库、上传状态、处理失败、删除确认和读取受限状态。
- EPUB/PDF/TXT 阅读位置保存与恢复。
- 公共书目搜索、版本选择、评分、短书评可见性、剧透标记和讨论。
- 书目提交、资料来源必填、审核状态、资源申请与授权错误。
- 私有内容不会出现在公共页面、Feed、推荐、个人资料和搜索结果。

完成每个 Frontend 迭代后至少运行：

```bash
cd Atoman-Frontend
bun run type-check
```

关键的私有资源访问、阅读进度恢复、书目审核和公共资源下架流程增加 Vitest 与 Playwright 验证。

## 11. 实现前需冻结的技术参数

以下参数不改变已确认的产品方向，但应在每个相关迭代开始前确定：

- 单用户存储配额、单文件大小、页数、章节数、处理时长和并发上传数。
- 病毒扫描引擎、对象存储隔离策略、签名 URL 有效期和删除保留窗口。
- EPUB 渲染库、PDF 阅读组件、TXT 分页策略和客户端缓存规则。
- 私有全文索引的保存位置、索引上限、撤销与删除策略。
- 书目搜索字段、排序、分页上限和 ISBN 去重规则。
- 书目贡献投票是否影响审核优先级，以及审核台的队列排序和批量操作。
- 公共资源授权证据的可接受类型、审核记录保留期和资源下架申诉流程。
- 私有书架是否在后续版本支持有限公开，以及该能力对隐私和推荐的影响。

## 12. 完成定义

每个迭代完成前必须满足：

- 产品行为、权限边界、状态机、失败处理和 API 变更已写入模块文档。
- 私有正文、元数据、阅读进度、笔记和全文索引均无法被无权用户获得。
- 公共书目、私有导入、公共正文资源和书评的可见性规则彼此独立且有自动化测试。
- 文件处理、删除、审核、下架和恢复具备可观察的状态、日志和审计记录。
- Backend 构建和受影响测试通过，Frontend 类型检查和受影响测试通过。
- 关键桌面端与移动端页面完成视觉验证，且不会出现私有资源入口或状态泄露。
