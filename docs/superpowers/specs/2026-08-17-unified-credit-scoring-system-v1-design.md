# 指数信用权重下的统一用户与内容评分系统

## Atoman 百分制信用与五星内容评价 V1 的模型及工程方案

- 日期：2026-08-17
- 状态：草案，待评审
- 版本：V1.2
- 范围：Atoman 全站用户、内容、互动与推荐系统

## 摘要

本文提出一套面向多内容形态社区的统一信用评分系统。每个用户拥有独立的 `0.0~100.0` 信用分，新用户初始为 `60.0`；所有用户都可以评分和收藏，但只有信用高于 `60.0` 时才产生公共权重。公共权重随信用指数增长，并满足 100 分用户的单次评价权重等于 70 分用户的 100 倍。

内容评价只保留两种用户动作：`0.5~5.0` 的半星评分和二元收藏。公开星级采用信用加权的贝叶斯平均；收藏采用信用加权、饱和增长和来源集中度修正；二者共同形成用于总榜的内容综合分，最近热门则额外考虑近期收藏及增长速度。系统同时计算有效评价人数和来源集中度，避免一个高信用用户被误表示为多数人共识。

本文进一步给出事件账本、快照、重算、反操纵边界和渐进迁移方案。用户信用的初始值、公共门槛、指数影响力、不活跃下限以及内容评价模型已经确认；用户信用如何根据创作和协作证据增长仍待下一轮设计确认，因此本文不把候选增长公式写成最终规则。

**关键词：** 信用系统；指数权重；贝叶斯评分；五星评价；收藏；有效样本量；推荐排序；协作贡献

## 1. 引言

内容社区通常同时维护用户等级、点赞、五星评分、赞赏、收藏和独立的协作积分。过多互动语义会增加理解成本，也会为机械操作提供更多可利用入口。V1 因此只保留两个进入统一内容评分的动作：半星评分表达质量，收藏表达推荐与长期兴趣。现有模块中的点赞可以继续作为局部社交功能，但不进入统一信用、内容综合分或用户信用增长。

统一信用系统的目标不是把所有信号粗暴相加，而是建立一条统一的因果链：

```text
已确认的创作与协作证据
        ↓
用户信用（0.0~100.0）
        ↓
指数评价权重
        ↓
半星评分 / 收藏
        ↓
公开星级、收藏强度与可信度
        ↓
总榜综合分 / 最近热门分
        ↓
下一周期用户信用证据（规则待定）
```

声誉系统研究长期指出，聚合反馈的关键不只是反馈数量，还包括反馈者可靠性、反馈相互依赖和操纵成本[1]、[2]、[7]。本文不试图在 V1 中复现 PageRank、EigenTrust 或复杂社会图算法[3]、[4]，而是选择一个可解释、可审计、可逐步上线的指数信用权重模型。

## 2. 问题定义

### 2.1 系统实体

记：

- 用户集合为 \(U\)；
- 可评价目标集合为 \(T\)；
- 内容目标集合为 \(T_C \subseteq T\)；
- 用户目标集合为 \(T_U \subseteq T\)；
- 结算周期为 \(e\)，V1 中一个周期为一个自然日；
- 行为类型集合为 \(M=\{Rating,Favorite\}\)；
- 评分值 \(r\in\{0.5,1.0,\ldots,5.0\}\)；
- 内容指标包括质量 \(Q\)、收藏强度 \(F\)、综合分 `ContentScore` 和最近热门分 `HotScore`。

目标不只包括音乐、博客和视频。论坛主题、评论、歌词注释、协作修订、用户主页等都可以通过稳定的 `(target_type, target_id)` 被引用。目标适配器负责判断某类对象是否可见、可互动、由谁创建以及有哪些贡献者。

### 2.2 核心目标

系统需要满足以下目标。

**G1：单一信用来源。** 每个用户只有一个全站信用分，不按音乐、视频、博客或论坛分别维护领域信用。

**G2：指数影响。** 用户信用只决定其每条有效评分或收藏的权重，不因其他用户加入而稀释；100 分用户的单次权重是 70 分用户的 100 倍。

**G3：行为简化。** 统一内容评价只保留半星评分和收藏，每个用户对同一目标各有一个当前状态。

**G4：中性初始信用。** 新注册用户信用为 `60.0`，可以评分和收藏；只有当前信用高于 `60.0` 时，行为才产生公共权重。

**G5：贡献驱动信用。** 单纯发布、评分或收藏不直接增加用户信用。已确认方向是由内容成果和被采纳协作形成信用证据，具体增长公式待后续确认。

**G6：展示与排序分离。** 公开星级只由评分决定；收藏不能改变公开星级，但与星级共同进入总榜和最近热门。

**G7：慢速反馈。** 内容投影可以分钟级更新，用户信用只按日更新，并只能使用前一周期已经封账的数据。

**G8：带下限的不活跃衰减。** 用户连续 90 天没有有效贡献后，高于初始基准 `60.0` 的信用逐渐向 `60.0` 下降，但不会仅因不活跃降到该基准以下。

**G9：可解释与可重算。** 所有影响用户信用或内容评分的事件必须可审计、可撤销、可按算法版本重放。

### 2.3 非目标

V1 不解决以下问题：

- 不把账号真实性识别作为评分算法的一部分。机器人、批量注册和身份关联由独立风控系统处理。
- 不引入 PageRank、EigenTrust、图神经网络或机器学习排序。
- 不建立领域信用。
- 不以信用替代内容审核、权限控制或违法内容治理。
- 不把真实货币支付或免费赞赏按钮纳入 V1 信用系统。
- 不承诺信用是社会身份、专业资质或事实正确性的证明。

### 2.4 威胁模型

虽然账号真实性在系统外处理，V1 仍需抵抗普通产品层面的操纵：

- 重复评分、删除后重评或取消收藏后立即重新收藏；
- 自己评价或收藏自己的内容；
- 两个或多个真实用户长期互相评分或收藏；
- 高信用用户短期集中操纵某个目标；
- 通过大量低质量发布获得创作分；
- 通过广撒网方式投机“早期发现者”奖励；
- 删除、修改或隐藏内容后仍保留历史收益；
- 信用变化立即反向改变当天已经发生的评价。

系统不声称完全消灭协同行为，但必须限制其收益上界、减慢反馈速度并保留审计证据。

## 3. 统一的边界

### 3.1 一套系统不等于一个数值

本文区分三个不同层次：

1. **用户信用 \(R_i\)**：对用户历史贡献可靠性的估计，取值为 `0.0~100.0`，新用户初始为 `60.0`。
2. **评价权重 \(w_i\)**：用户 \(i\) 的每条有效评分或收藏所使用的指数权重。
3. **目标派生指标**：公开星级、收藏强度、可信度、内容综合分和排序特征。

三者都不承担全站总量守恒。新增用户不会降低其他用户的信用或单次评价权重；同一用户可以评价多个目标，因此 V1 也不声明该用户跨目标影响力总和固定。系统通过每目标状态唯一、指数门槛、有效样本量、来源集中度和独立风控限制滥用。

本文所说的“统一”是指：全站使用同一信用分、同一权重门槛、同一事件账本和同一内容综合价值框架，而不是把所有统计量合并成一个无法解释的数值。

### 3.2 评价不是转账

用户评分或收藏内容时不损失自己的信用，也不会立即获得信用。信用仅决定当前评价的公共权重。

- 每个用户对每个目标只有一个当前星级和一个收藏状态；
- 修改评分会替换旧值，不会叠加第二票；
- 取消收藏会撤销收藏权重；
- 同一用户评价更多目标不会降低其既有评价权重；
- 因此跨目标总影响力不固定，批量异常评价必须由频率限制和风控处理。

### 3.3 一个信用权重，两个内容信号

**星级 \(Q\)** 回答“具有公共权重的用户认为内容质量如何”，公开展示为 `0.5~5.0` 星。

**收藏 \(F\)** 回答“具有公共权重的用户是否愿意长期保留或推荐该内容”，只进入收藏强度和排序。

二者使用同一个用户指数权重，但保持统计语义独立；最终在 `ContentScore` 和 `HotScore` 中共同计算。

## 4. 用户信用与指数评价权重

### 4.1 百分制用户信用

用户 \(i\) 在周期 \(e\) 的正式信用为：

\[
R_i^{(e)}\in[0,100],\qquad R_i^{(0)}=60.0
\]

内部累积计算保留高精度，每日结算时生成四舍五入到一位小数的正式快照。公共权重只读取正式快照；例如内部累计值 `60.04` 发布为 `60.0` 时，公共权重仍为 0。前台显示值与实际门槛状态必须一致。

### 4.2 指数影响力

定义信用到单次评价权重的映射：

\[
\Phi(R)=
\begin{cases}
0, & R\le60\\
\dfrac{e^{\lambda(R-60)}-1}{e^{40\lambda}-1}, & 60<R\le100
\end{cases}
\]

要求：

\[
\frac{\Phi(100)}{\Phi(70)}=100
\]

解得：

\[
\lambda\approx0.1446630231
\]

候选权重表如下：

| 正式信用 | 单次评价权重 | 相对 70 分 |
| ---: | ---: | ---: |
| 60.0 | 0 | 0 |
| 60.1 | 0.0000449 | 0.0045 倍 |
| 65.0 | 0.0032666 | 0.3267 倍 |
| 70.0 | 0.0100000 | 1 倍 |
| 80.0 | 0.0524877 | 5.2488 倍 |
| 90.0 | 0.2330084 | 23.3008 倍 |
| 95.0 | 0.4835565 | 48.3557 倍 |
| 100.0 | 1.0000000 | 100 倍 |

用户 \(i\) 在周期 \(e\) 的评分和收藏都使用：

\[
w_i^{(e)}=\Phi\left(R_i^{(e)}\right)
\]

该权重直接作用于每个目标，不在用户评价过的不同目标之间分摊。信用 `≤60.0` 的用户仍可保存评分和收藏，但公共权重为 0；信用跨过门槛后，当前有效状态在下一周期自动获得权重，降回门槛时自动归零。

### 4.3 带下限的不活跃衰减

设用户距离最后一次有效贡献已经过去 \(d_i\) 天。登录、浏览、机械评分、单纯发布以及旧内容分数保持不变都不刷新该时间；内容获得新的独立有效评价、协作成果被采纳或完成被承认的维护可以刷新。

V1 设置 90 天宽限期和 90 天半衰期。超过宽限期、没有新有效贡献且信用高于 `60.0` 时，仅衰减超出中性基准的部分：

\[
R_i(d_i)=60+\left(R_i(90)-60\right)2^{-\frac{d_i-90}{90}},\quad R_i(90)>60
\]

因此不活跃信用逐渐向 `60.0` 收敛。处罚已经使信用低于 `60.0` 时，不活跃既不会继续扣分，也不会自动恢复到 `60.0`。用户重新产生有效贡献时，以当时已经衰减的信用为新基线。

### 4.4 权重边界

该模型只保证单个用户对单个目标最多贡献 \(1.0\) 权重，并保证同一行为状态不重复累计。它不保证单个用户跨所有目标的权重总和固定，也不保证全站权重总量固定。批量跨目标评分、批量账号和关联群体操纵必须由状态唯一性、速率限制、来源集中度和独立风控处理。

## 5. 评价行为与状态

### 5.1 仅保留星级和收藏

V1 统一内容评分只接收两种行为：

| 行为 | 取值 | 统计语义 |
| --- | --- | --- |
| 星级评分 | `0.5, 1.0, ..., 5.0` | 明确质量判断 |
| 收藏 | `true / false` | 推荐与长期兴趣 |

每个用户对同一目标最多有一个当前星级和一个当前收藏状态。所有半星档位使用相同的用户权重；`5.0` 星不会比 `0.5` 星拥有更多投票权，差异只在评分值本身。

点赞、赞赏、浏览、播放、评论数、转发数和粉丝数不进入 V1 内容综合分，也不直接增加用户信用。现有模块可以保留这些产品功能，但统一评分核心不消费它们。

### 5.2 当前状态与事件历史

系统同时保留当前状态和不可变事件：

- 首次评分、修改评分和删除评分都追加事件；
- 当前状态表只保留最后一个有效半星值；
- 收藏和取消收藏都追加事件；
- 当前状态表只保留是否收藏；
- 重复请求通过客户端事件 ID 或服务端幂等键去重；
- 删除后立即重评、取消后立即收藏不能制造多条当前票。

评分和收藏使用独立唯一键 `(actor_user_id, target_type, target_id, interaction_type)`。用户可以同时评分和收藏同一内容，因为二者语义不同。

### 5.3 长期状态与最近窗口

总榜读取当前有效评分和收藏，不对仍然有效的状态设置统一 180 天过期。用户删除评分或取消收藏时，相应证据撤销；用户信用变化时，状态使用下一周期的新权重重算。

最近热门只读取最近窗口内新增的有效收藏及其增速。为防止反复取消再收藏刷新时间，状态需要记录 `first_activated_at`、`effective_since`、`last_changed_at` 和 `recent_eligible_at`；未达到重新计入冷却条件的再次收藏不视为新的热门事件。

## 6. 指数权重投影

### 6.1 单条评分权重

用户 \(i\) 对内容 \(j\) 的有效评分权重为：

\[
W_{ij,Q}^{(e)}=w_i^{(e)}\cdot Eligible_{ij,Q}
\]

其中 `Eligible` 排除自评、利益相关评价、被撤销事件和不可评价目标。评分值 \(r_{ij}\) 与权重分离，取值为 `0.5~5.0`。

### 6.2 单条收藏权重

用户 \(i\) 对内容 \(j\) 的有效收藏权重为：

\[
W_{ij,F}^{(e)}=w_i^{(e)}\cdot Favorite_{ij}\cdot Eligible_{ij,F}
\]

`Favorite` 只有 0 或 1。收藏没有等级，不因重复操作叠加。

### 6.3 明确的非守恒边界

对任意用户和目标：

\[
0\le W_{ij,Q}^{(e)}\le1,
\qquad
0\le W_{ij,F}^{(e)}\le1
\]

但同一用户评价 \(m\) 个目标时，其跨目标总权重最多可随 \(m\) 线性增长。V1 不使用全站池、个人预算分摊、通道预算或空闲容量归一化。这使每条评分的解释保持稳定，也意味着批量跨目标评价必须单独监控。

## 7. 五星内容评分

### 7.1 信用加权贝叶斯平均

设内容 \(j\) 的类型为 \(\tau(j)\)。类型先验平均星级为 \(\mu_\tau\)，先验权重为 \(K_\tau\)。公开星级的内部估计为：

\[
Q_j=
\frac{
K_\tau\mu_\tau+
\sum_iW_{ij,Q}r_{ij}
}{
K_\tau+
\sum_iW_{ij,Q}
}
\]

其中 \(r_{ij}\in\{0.5,1.0,\ldots,5.0\}\)。所有半星档位的权重都等于 \(W_{ij,Q}\)，五星不会比半星拥有更多权重。

星级先验 \(\mu_\tau\) 表示同类内容在证据不足时的内部参考均值；先验权重 \(K_\tau\) 表示该参考均值相当于多少总评价权重。它不是虚构用户数。例如 \(\mu=3.5,K=0.5\) 表示先放入一份“总权重 0.5、评分 3.5 星”的历史基准。一个权重为 1 的 100 分用户给出五星时：

\[
Q=\frac{0.5\times3.5+1\times5}{0.5+1}=4.5
\]

没有先验时该内容会立即成为五星。随着真实评价权重增加，先验影响自动减弱。先验只用于内部稳定，不能在没有足够评价时作为真实社区星级展示。

### 7.2 评分资格

以下评分公共权重为 0：

- 内容所有者及已确认直接贡献者评价自己的内容；
- 已删除、隐藏或不可评价目标上的状态；
- 被风控、管理员或申诉流程撤销的状态；
- 当前正式信用不高于 `60.0` 的用户评分。

所有用户仍可保存个人评分。正式信用跨过门槛时，当前评分在下一周期自动启用；信用降回门槛时自动停用。

### 7.3 有效评价人数与集中度

真实评价人数不能代替独立有效证据。定义总评分权重：

\[
S_{Q,j}=\sum_iW_{ij,Q}
\]

Kish 有效评价人数为[9]：

\[
n_{eff,j}=
\frac{\left(\sum_iW_{ij,Q}\right)^2}
{\sum_iW_{ij,Q}^2}
\]

最大单用户集中度为：

\[
c_{Q,j}=
\begin{cases}
\dfrac{\max_iW_{ij,Q}}{S_{Q,j}}, & S_{Q,j}>0\\
1, & S_{Q,j}=0
\end{cases}
\]

候选公开条件为 `n_eff >= 3`、总权重达到类型门槛且来源集中度未触发风险规则。不满足时前台显示“暂无足够评价”；内部仍可计算影子值。前台同时显示一位小数星级和真实评价人数，不把 \(n_{eff}\) 伪装成用户数。

## 8. 收藏、内容综合分与榜单

### 8.1 收藏强度

设 `Favorite_ij` 为当前收藏状态，则内容加权收藏强度为：

\[
S_{F,j}=\sum_iW_{ij,F}
\]

按内容类型使用饱和参数 \(L_{F,\tau}\)：

\[
F_j=1-e^{-S_{F,j}/L_{F,\tau}}
\]

收藏越多，新增收藏的边际收益越低。设最大单用户或最大关联群体占比为 \(c_{F,j}\)，候选集中度修正为：

\[
F_{adjusted,j}=F_j\left(1-\beta c_{F,j}\right)
\]

\(\beta\) 可从 `0.3` 开始影子评估。该修正降低来源高度集中的收藏强度，但不会把单个高信用用户的真实收藏完全清零。

### 8.2 内容综合分

公开星级只由评分决定。总榜另行使用内部内容综合分。先将星级归一化：

\[
Q_{normalized,j}=\frac{Q_j-0.5}{4.5}
\]

当前候选公式为：

\[
ContentScore_j=
100\left(
0.7Q_{normalized,j}
+0.3F_{adjusted,j}
\right)
\]

`70%` 星级和 `30%` 收藏是待影子校准的起点，不是最终参数。收藏最多提供有限推荐贡献，不能直接改变公开星级，也不能轻易掩盖明显低星内容。证据不足的内容不进入总榜，只进入最新流和探索候选。

### 8.3 最近热门

最近热门保留质量底线，并提高最近 7 天收藏的作用。候选输入包括：

- 经过先验与资格规则处理的星级质量；
- 最近 7 天新增有效收藏强度；
- 最近收藏增长速度；
- 有限的新鲜度修正。

候选形式为：

\[
HotScore_j=
100\left(
\alpha_hQ_{normalized,j}
+\beta_hF_{j,7d}
+\gamma_hVelocity_{j,7d}
+\zeta_hFreshness_j
\right)
\]

其中各系数之和为 1。具体比例尚未确认，必须通过历史重放和线上实验校准。取消后立即重新收藏不能重复计入最近增长。

### 8.4 展示边界

内容页只需要公开：

- 一位小数的平均星级；
- 真实评价人数；
- 真实收藏人数；
- 证据不足状态。

`ContentScore`、`HotScore`、指数权重、有效评价人数和集中度属于内部排序与审计指标，不应伪装成第二套公开内容评分。

### 8.5 完整计算示例

以下参数只用于解释：\(\mu=3.5\)、\(K=0.5\)、\(L_F=2\)、\(\beta=0.3\)，综合分暂按星级 70%、收藏 30%。某内容收到：

| 用户组 | 人数 | 信用 | 单人权重 | 星级 |
| --- | ---: | ---: | ---: | ---: |
| A | 1 | 100 | 1.0000 | 5.0 |
| B | 5 | 90 | 0.2330 | 4.0 |
| C | 10 | 80 | 0.0525 | 4.5 |
| D | 20 | 70 | 0.0100 | 3.5 |

总评分权重约为 `2.890`，加权星级和约为 `12.722`，因此：

\[
Q=\frac{0.5\times3.5+12.722}{0.5+2.890}\approx4.269
\]

前台四舍五入显示 `4.3` 星。36 名真实评价者的有效评价人数约为：

\[
n_{eff}\approx6.42
\]

若其中 1 名 100 分、3 名 90 分、4 名 80 分和 5 名 70 分用户收藏，则真实收藏人数为 13，加权收藏强度约为：

\[
S_F=1+3\times0.233+4\times0.0525+5\times0.01\approx1.959
\]

饱和值 \(F\approx0.6245\)。最大来源占比约为 `51.0%`，集中度修正后：

\[
F_{adjusted}\approx0.5289
\]

星级归一化值约为 `0.8376`，候选综合分为：

\[
ContentScore=100(0.7\times0.8376+0.3\times0.5289)\approx74.5
\]

最终前台只显示“`4.3` 星、36 人评价、13 人收藏”；内部总榜使用 `74.5`。

## 9. 用户信用增长：已确认边界与待定项

### 9.1 已确认的信用来源

当前只确认两类正向来源：

- `Creation`：用户作为作者或共同创作者，其内容获得有效星级和收藏认可；
- `Collaboration`：用户提交的编辑、修订、标注、整理或协作成果被正式采纳。

发布数量、评分数量、收藏数量、点赞、赞赏、浏览和登录均不直接增加用户信用。收藏已经通过内容综合价值进入创作证据，不能再单独给作者加一次分。

### 9.2 创作与协作归因原则

内容价值只能按已确认贡献份额归因。设用户 \(i\) 对内容 \(j\) 的份额为 \(s_{ij}\in[0,1]\)，需要满足：

- 作者、共同创作者和被接受修订者的总份额由领域适配器校验；
- 用户自己的评分和收藏不能进入自己内容的价值；
- 内容分下降、删除、处罚或归因撤销时能够反向重算；
- 同一成果不能在创作和协作中重复计分；
- 静态内容分不能每天重复铸造新的信用证据。

协作事件必须由目标所有者、版主或确定性的领域流程确认，提交者不能自行采纳。

### 9.3 尚未确认的增长公式

用户已确认“分数越高，继续提升越困难”，但以下内容尚未定案：

- 创作与协作证据的比例；
- 内容综合分变化如何转换为创作证据；
- 达到 70、80、90、100 分分别需要多少累计证据；
- 证据是按当前成果存量计算，还是按不可重复的里程碑结算；
- 普通低质量成果是否只不加分，还是允许降低信用；
- 除作弊和撤销外，哪些事件可以把信用降到 `60.0` 以下。

此前讨论的指数证据成本可作为候选方案，但在确认上述语义前不写成正式信用更新公式。V1.2 文档中的指数函数只用于评价权重。

### 9.4 滞后结算

无论最终采用哪种增长公式，都遵守每日滞后：周期 \(e\) 的评分和收藏使用周期开始时的正式信用快照；由这些评价形成的创作证据最早在周期 \(e+1\) 进入用户信用计算。信用变化不能反向改写同一周期已经封账的输入。

### 9.5 不活跃与处罚

不活跃规则已经确认：连续 90 天没有有效贡献后，高于 `60.0` 的部分按 90 天半衰期向 `60.0` 收敛。处罚造成的低于 `60.0` 不因不活跃自动恢复。

作弊裁定、内容撤销和协作归因撤销必须保留独立事件并支持重算。普通低星评价是否构成用户负向证据仍待后续讨论，当前不得直接据此处罚作者。

## 10. 形式化性质

### 10.1 性质一：门槛严格

若 \(R_i\le60\)，则 \(\Phi(R_i)=0\)，因此该用户的评分和收藏都不会改变公共结果。用户状态仍被保存，门槛只控制公共投影。

### 10.2 性质二：100 分与 70 分的权重比固定

由 \(\lambda\) 的校准条件：

\[
\frac{\Phi(100)}{\Phi(70)}=100
\]

该比例不依赖用户总数、目标总数和其他用户信用。

### 10.3 性质三：同一目标上的重复操作不叠加

评分与收藏各自使用当前状态唯一键。因此同一用户反复提交相同操作只能替换或保持状态，不能在同一目标上累积多票。

### 10.4 性质四：高分评价者不等于多数共识

加权平均允许高信用用户产生更大方向影响，但 \(n_{eff}\) 和来源集中度独立衡量证据广度。一个 100 分用户可以拥有 100 个 70 分用户的数值权重，仍然只代表一个独立来源，不能自动满足公开可信度或总榜准入条件。

### 10.5 性质五：先验影响随真实证据下降

贝叶斯星级中先验占比为：

\[
\frac{K_\tau}{K_\tau+\sum_iW_{ij,Q}}
\]

真实总权重增加时该比例单调下降并趋近于 0，因此先验只能稳定冷启动，不能永久支配成熟内容。

### 10.6 性质六：不活跃衰减有下限

对起始信用高于 `60.0` 且持续不活跃的用户：

\[
R_i(d_i)>60,
\qquad
\lim_{d_i\to\infty}R_i(d_i)=60
\]

处罚造成的低于 `60.0` 不在该衰减公式中自动恢复。

### 10.7 明确不具备的性质

V1.2 不保证用户跨目标总权重有界，也不保证全站评价权重总量固定。一个用户评价更多目标会产生更多边，更多达到门槛的用户也会增加全站总权重。这是取消总量与预算分摊后的明确取舍。

## 11. 数据架构

### 11.1 设计原则

统一系统需要统一账本和目标引用，但不要求把所有业务对象迁移到一张 `contents` 表。Atoman 的音乐、博客、视频、论坛、评论、歌词注释和协作修订具有不同生命周期、所有权和可见性规则。使用多态目标引用和领域适配器更符合现有模块边界。

核心写模型与计算投影分离：

```text
业务动作
   ↓
当前状态 + 不可变事件 + Outbox
   ↓
影响力投影 Worker
   ↓
目标评分投影
   ↓
每日信用结算
```

evaluation_weight

```

唯一键为 `(epoch, user_id)`。

#### `interaction_events`

client_event_id

```

`client_event_id` 或服务端幂等键必须唯一。

业务状态、互动事件和 Outbox 必须在同一数据库事务中提交，避免互动成功但评分投影永久漏算。

### 11.3 目标适配器

统一评分核心不直接依赖博客、音乐、视频、论坛或评论服务。每个模块注册目标适配器，提供：

- 目标是否存在；
- 当前用户是否可见和可互动；
- 稳定目标标识；
- 内容类型；
- 目标所有者和贡献者；
- 是否允许半星评分和收藏；
- 是否处于已发布、已删除或被隐藏状态；
- 删除、合并或修订后如何迁移或撤销影响力。

该模式与 Atoman 现有统一评论目标注册方式一致，可以复用类似的模块边界，而不复制各模块可见性逻辑。

## 12. 计算流程

### 12.1 评分与收藏写入

用户评分或收藏时：

1. 认证用户并解析目标适配器。
2. 校验目标可见性、自评与利益相关规则。
3. 校验评分值属于 `0.5~5.0` 的半星集合，或收藏值为布尔状态。
4. 在一个事务中追加 `interaction_events`。
5. 同一事务中更新唯一的 `interaction_states` 当前状态。
6. 同一事务中写入 `scoring_outbox`。
7. Worker 读取当前周期正式信用快照并计算 \(\Phi(R_i)\)。
8. Upsert 对应的 `evaluation_edges`。
9. 将目标加入聚合队列，重算星级、有效人数、集中度、收藏强度和榜单分。

请求事务不扫描用户其他目标，也不执行跨目标预算重分配。

### 12.2 每日信用快照与重投影

用户信用增长公式尚未确认，因此 V1.2 只固定以下顺序：

1. 封闭上一周期评分、收藏和内容快照。
2. 计算已确认的创作、协作、撤销和处罚证据。
3. 按最终用户信用规则计算高精度中间值。
4. 应用已确认的不活跃下限规则。
5. 四舍五入发布一位小数的正式信用快照。
6. 根据正式值计算指数评价权重。
7. 对权重变化用户的当前评分和收藏分批重投影。
8. 重算受影响目标并原子发布新周期快照。

结算失败时继续使用上一周期完整快照，不发布部分完成的新周期。

### 12.3 最近热门推进

总榜状态本身不按统一窗口过期。最近热门需要按时间窗口推进最近 7 天收藏强度和增长速度；Worker 可以按收藏发生时间和 `recent_eligible_at` 增量更新，不需要每日扫描所有历史评分。

## 13. 与 Atoman 现状的关系

### 13.1 现有互动存储

Atoman 当前至少存在以下独立互动模型：

- 博客与短话使用 `Like`；
- 论坛主题使用 `ForumLike`；
- 统一评论使用 `CommentLike`；
- 音乐编辑使用 `MusicEditVote`；
- 歌词注释使用 `MusicLyricAnnotationVote`；
- 辩论使用 `DebateVote`；
- 收藏和内容消费分散在各模块表及 `ContentLifecycleEvent` 中。

V1 不应一次性删除这些业务状态表。现有点赞、论坛投票和消费事件继续服务各自模块，但不进入统一内容评分，也不能自动迁移成收藏，因为语义不同。统一评分只桥接明确的半星评分和收藏；缺少对应业务状态的模块需要新增能力后再接入。

### 13.2 现有论坛信用

当前 `ForumTrustService` 主要依据账号年龄、论坛主题与回复数量、独立点赞者数量计算 0 至 3 级论坛信任，并使用历史最高等级避免下降。它适合作为论坛发帖频率和旧数据迁移的参考，但不满足全站百分制信用、`60.0` 公共权重门槛、带下限的不活跃衰减和多内容协作归因要求。

迁移期应保持旧论坛权限逻辑稳定。新统一信用先影子运行，不直接替换现有论坛限流和权限；待评分稳定性通过评估后，再单独设计权限映射。

### 13.3 现有推荐系统

现有推荐模块已经使用质量、趋势、新鲜度、权威、曝光和编辑等候选特征。统一信用系统应把 `ContentScore`、`HotScore`、加权星级和收藏增长作为新特征来源，而不是改变现有推荐 API 和全部页面路由。

### 13.4 现有通用事件与目标模型

`ContentLifecycleEvent` 已经使用 `content_type + content_id` 记录内容事件；统一评论使用 `DiscussionTarget` 和目标适配器处理跨模块目标。这些模式证明多态目标引用在当前架构中可行。统一信用系统应建立自己的严格目标类型注册表，并复用相同的适配器思想。

## 14. 复杂度与性能

设：

- 用户 \(i\) 当前共有 \(m_i\) 个评分和收藏状态；
- 目标 \(j\) 共有 \(n_j\) 条评价边；
- 全站当前状态边数为 \(E\)。

单次评分或收藏只更新一个当前状态和一条评价边。使用增量维护总权重、加权星级和权重平方和时，写入后的基础聚合可以做到均摊 \(O(1)\)；需要完整来源聚类或审计时为 \(O(n_j)\)。

用户信用变化后，该用户所有当前评价边都需要使用新快照重投影，复杂度为：

\[
O(m_i)
\]

由于总榜状态不统一过期，\(m_i\) 和 \(E\) 会随长期使用增长。V1 通过每用户每目标每行为唯一键、异步重投影、按用户分区和冷目标降频控制成本。后续可以采用：

- 信用权重变化低于阈值时延迟重投影；
- 批量 SQL 更新边并按目标聚合；
- 用户和目标队列分片；
- 最近热门按时间桶增量维护；
- 不可变事件按时间分区或归档；
- 算法版本化的离线重算。

不能依赖删除旧评分来控制规模；评分与收藏是用户当前明确状态，只有用户撤销、目标失效或治理裁定时才退出总榜。

## 15. 一致性、幂等与重算

评分系统是业务状态的派生投影，不应成为评分或收藏动作成功的同步前提。

系统需要满足：

- 同一事件重复投递只产生一次状态变化；
- 事件顺序由每个用户与目标的版本号约束；
- 投影 Worker 可以安全重试；
- 每条边记录使用的信用快照和算法版本；
- 每个目标快照记录完整输入版本；
- 删除或撤销事件可以触发反向重算；
- 新算法可以从事件与状态重建影子投影；
- 新周期只能整体发布，不能让部分评价边使用新信用权重、部分仍使用旧权重。

信用计算、指数权重和贝叶斯聚合需要稳定精度。数据库应使用高精度 `numeric` 或定点整数保存 `credit_accumulator` 和评价权重中间值；每日封账后生成一位小数的 `credit_score` 正式快照，API 与公共权重都读取该值。不得让隐藏精度跨越 `60.0` 公共门槛。

## 16. 风险与防护

### 16.1 协同评分与收藏

多个高信用用户仍可集中评分或收藏同一群体内容。V1 采用：

- 自评和直接利益相关边排除；
- 每用户每目标每行为唯一状态；
- 有效评价人数独立于数值权重；
- 最大用户和最大关联群体集中度监控；
- 用户信用使用上一周期正式快照；
- 异常互评、同步收藏和群体集中度检测。

复杂图检测留给后续版本。

### 16.2 高信用账号被盗

高信用账号的单次评价权重更大，账号被盗后可能批量影响多个目标。系统需要异常登录检测、敏感操作二次确认、批量评分速率限制、临时冻结权重和事件撤销能力。

### 16.3 门槛冷启动与批量账号

新用户从 `60.0` 开始，可以保存评分和收藏，但公共权重为 0。新账号必须通过已确认内容成果或被采纳协作提高信用；基本发布和新内容曝光不能被信用门槛阻断。

若攻击者能够批量把账号提升到 `60.0` 以上，总影响力会随账号数量和操作目标数量增长。门槛只能阻止新注册账号立即刷分，不能替代账号关联、频率限制和独立风控。

### 16.4 跨目标批量评价

取消个人预算分摊后，高信用用户可以在多个目标上重复使用同一权重。正常用户广泛评分是允许行为，但短时间机械评分、固定星级模式和异常收藏序列需要进入风控。该风险必须在上线报告中单独衡量，不能用“单目标唯一”掩盖。

### 16.5 贝叶斯先验偏差

统一先验可能掩盖内容类型差异。上线前需要按音乐、文章、视频等类型评估历史星级分布；没有数据时先验只作为内部影子值，不直接公开。\(K\) 过大会压制新内容，过小会让少量高权重评分剧烈改变结果。

### 16.6 反馈循环

内容综合分未来会成为用户创作证据，而用户信用又决定评分权重。每日滞后只能减慢循环，不能从数学上消除它。用户信用增长设计必须避免每天重复使用同一静态内容分，并支持内容撤销和贡献归因回滚。

## 17. 评估方法

### 17.1 影子运行

正式影响排序前，系统至少影子运行 30 至 60 天：

- 接收真实评分和收藏事件；
- 计算指数评价边、星级、有效人数、收藏强度和榜单分；
- 不向用户显示新信用，不改变现有推荐结果；
- 每日生成旧系统与新系统对比报告；
- 使用历史重放测试候选参数。

### 17.2 正确性指标

必须持续监控：

- 用户信用是否保持在 `0.0~100.0` 并显示一位小数；
- 新用户是否初始化为 `60.0`；
- `R ≤ 60.0` 是否严格产生零公共权重；
- `\Phi(100) / \Phi(70)` 是否等于 100；
- 同一用户和目标是否只有一个评分状态和一个收藏状态；
- 自评和利益相关评价是否被排除；
- 修改、删除评分或取消收藏后投影是否正确撤销；
- 有效评价人数和集中度是否可从边重算；
- 信用变化后评价边是否使用同一周期快照；
- 不活跃信用是否向 `60.0` 收敛；
- 重复事件是否幂等，新周期是否原子发布。

### 17.3 分布与治理指标

需要分析：

- 用户信用分布与 Gini 系数；
- 信用高于 `60.0` 的用户比例；
- 评分和收藏权重的前 1%、前 10% 来源占比；
- 内容最大单用户和最大关联群体权重占比；
- 真实评价人数、有效评价人数和二者比值；
- 评分互惠、同步收藏和跨目标批量操作比例；
- 90 天后不活跃信用向 `60.0` 收敛的速度；
- 新用户从 `60.0` 首次升到门槛以上所需时间；
- 新内容获得第一次有效评价所需时间；
- 信用日变化的均值、分位数和异常峰值。

### 17.4 推荐效果指标

离线指标不能替代在线实验。正式接入推荐后，应分阶段观察：

- 有效消费率；
- 完成率；
- 收藏后消费率；
- 负反馈和快速退出率；
- 内容类型与创作者曝光多样性；
- 新内容进入候选集的比例；
- 高质量低曝光内容的发现率；
- 用户对评分解释的理解和申诉率。

不能只以点击率判断系统成功，否则系统可能偏向标题刺激和短期热度。

### 17.5 参数敏感性

至少对以下参数进行网格或分层实验：

- 公共权重门槛和指数参数 \(\lambda\)；
- 各内容类型的先验均值 \(\mu_\tau\) 与先验权重 \(K_\tau\)；
- 公开星级的总权重、有效人数和集中度阈值；
- 收藏饱和参数 \(L_{F,\tau}\) 与集中度系数 \(\beta\)；
- `ContentScore` 的星级/收藏比例；
- `HotScore` 的窗口和各输入比例；
- 不活跃宽限期与半衰期；
- 后续确认的用户信用增长参数。

参数选择应优先满足门槛正确、星级稳定、来源多样和产品可解释，再优化推荐效果。

## 19. 渐进实施路线

### 阶段 0：规则冻结

- 审核已确认规则，并明确用户信用增长公式仍未定案。
- 明确哪些目标允许半星评分和收藏。
- 明确协作采纳和贡献归因规则。
- 决定现有用户的冷启动种子政策。
- 决定哪些治理处罚可以影响信用。

### 阶段 1：账本与投影基础设施

- 增加信用账户、快照、事件、状态、评价边、目标快照、贡献归因和 Outbox 表。
- 建立目标适配器注册表。
- 实现算法版本和重算能力。
- 不改现有 API 返回和推荐结果。

### 阶段 2：评分与收藏桥接

- 只接入语义明确的半星评分和收藏。
- 不把现有点赞、论坛投票或播放事件自动映射成收藏。
- 从已有收藏状态回填当前状态，并为新增评分能力建立独立事件。
- 对账原始状态、评价边和目标快照。

### 阶段 3：影子计算

- 运行指数权重、贝叶斯星级、收藏强度、总榜和最近热门影子投影。
- 每日检查门槛、权重比、有效人数、集中度和分布。
- 调整参数和目标级上限。
- 不公开用户信用，不改变推荐。

### 阶段 4：只读展示

- 对内部管理员展示信用构成、内容质量和可信度。
- 对少量测试用户展示解释页。
- 建立申诉、撤销和重算流程。

### 阶段 5：推荐接入

- 先把 `ContentScore` 和 `HotScore` 作为现有推荐的低权重特征。
- 通过分流实验逐步提高权重。
- 保留最新流、探索配额和编辑信号。

### 阶段 6：用户公开与旧系统迁移

- 公开稳定后的信用分与主要构成。
- 决定是否将论坛旧信任等级映射到统一信用或仅保留为权限等级。
- 在跨 Web、后端及后续客户端契约确认后更新 API 文档。
- 只有在所有消费者迁移完成后，才考虑删除旧互动或旧信任存储。

## 20. 冷启动与迁移种子

所有新注册用户统一从 `60.0` 开始，但只有高于 `60.0` 的用户才有公共权重。若上线时所有现有用户也都被设置为 `60.0`，系统将没有任何有效公共评价，无法产生第一批社区认可。因此迁移时仍需要受控地为已有贡献者计算高于门槛的初始信用。

候选方法包括：

1. 根据现有论坛信任等级、已发布内容、独立互动历史和协作采纳记录计算 `60.0~100.0` 的受限迁移信用。
2. 只为经过人工审核的历史贡献者设置高于 `60.0` 的种子信用，其余现有用户和所有新用户保持 `60.0`。
3. 使用历史事件离线重放计算初始信用，并对账号年龄、发布数量等弱证据设置严格上限。

推荐采用“历史重放加上限、人工审查极端值”的组合。现有论坛等级只能作为一个输入，不能直接映射为高信用，因为它当前主要基于数量、账号年龄和独立点赞人数，而且等级只升不降。

任何迁移信用都应记录来源、版本和迁移批次，并在后续正常结算中逐渐被真实贡献替代。迁移种子只发生一次，不能演变为新注册赠送公共权重。

## 21. 产品解释与用户权利

前台统一展示一位小数，不展示内部指数权重和计算精度。

用户信用页至少说明：

- 当前信用分和是否具有公共评价权重；
- 最近更新时间；
- 已确认的创作、协作、撤销和处罚证据；
- 是否处于不活跃衰减；
- 申诉入口。

内容页只展示：

- `0.5~5.0` 的一位小数平均星级；
- 真实评价人数；
- 真实收藏人数；
- “暂无足够评价”状态。

系统不公开其他用户对具体目标的精确指数权重、有效人数、集中度、`ContentScore` 或 `HotScore`，但应公开总体规则和个人可验证事件。

## 22. 局限与后续研究

V1 仍有以下局限：

- 一份全站信用无法表达不同领域的专业差异；
- 一个用户可以在多个目标上重复使用指数权重，跨目标总影响不受预算约束；
- 达到门槛的关联账号可以线性增加总影响力，因此系统依赖独立账号风控；
- 100 分与 70 分相差 100 倍会放大高信用账号误判和被盗风险；
- 创作价值存在曝光偏差，低曝光内容可能缺少评分和收藏；
- 贝叶斯先验和不同内容类型的评分文化需要长期校准；
- 用户信用增长公式尚未确定；
- 贡献份额在多人创作和复杂修订中可能存在争议；
- 当前模型不判断内容事实真伪，只聚合社区评价和收藏意愿。

在拥有足够数据后，可以研究：

- 基于恰当评分规则的 `Curator` 贡献；
- 来源群体独立性与图结构折扣；
- 领域专业信用作为全站信用的附加上下文，而非独立货币；
- 因果曝光校正；
- 鲁棒贝叶斯估计和异常群体降权；
- 差分隐私或隐私保护的公开统计；
- 对治理、申诉与算法公平性的定期审计。

## 23. 结论

本文当前确认了一套简化且可解释的评价核心：用户信用为 `0.0~100.0`，新用户从 `60.0` 开始，只有高于门槛才有公共权重；权重按指数曲线增长，并严格满足 100 分用户单次评价权重为 70 分用户的 100 倍。

统一内容评价只保留半星评分和收藏。公开星级使用信用加权贝叶斯平均，收藏使用饱和与集中度修正；有效评价人数防止高权重个体被误表示为多数共识。内部 `ContentScore` 支持总榜，近期收藏与增速支持最近热门，二者均不作为第二套公开评分。

用户信用增长公式尚未确认。下一阶段需要确定创作与协作证据如何结算、不同信用等级的证据成本以及负向内容结果是否影响用户信用。在这些规则确认前，不应开始数据库迁移或公开信用实现。
