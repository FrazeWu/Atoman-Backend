# Feed 全量投影：隔离写入批次实验（2026-11-04）

## 范围与安全

- 独立分支 `perf/feed-insert-batch-20261104`，基于滚动锚点及分段诊断分支 `7766a07`。生产 main 未修改，未执行任何生产 DDL、启用 Worker、GC、HTTP 投影路由或部署。
- 生产默认批次继续保持代表项 350、成员 300。只有同时设置 `FEED_SCALE_ISOLATED=yes` 和 `FEED_SNAPSHOT_BATCH_EXPERIMENT=yes`，才从专用实验变量读取 `FEED_SNAPSHOT_ROW_BATCH`、`FEED_SNAPSHOT_MEMBER_BATCH`。任一参数无效或超过 2,000 时退回默认值；2,000 条仍远低于本投影 INSERT 的 PostgreSQL 参数数目上限。
- 所有样本由原有 `scripts/test-feed-scale-isolated.sh 100000` 生成：独立临时 PostgreSQL 16 容器、1.5 CPU / 1.5 GiB、Go 1.5 CPU / 2.2 GB、14 分钟上限；所有文章和来源均为合成模拟数据，不包含生产文本或账号数据。每组顺序运行，测试完成后销毁临时数据库，未继承任何生产数据库 DSN。
- 观测变量 `FEED_SNAPSHOT_STAGE_TRACE=yes` 输出 fetch、annotate、materialize、insert_representatives、insert_members、publish_commit 各阶段耗时。事务性发布逻辑和出错回滚不变；实验不修改索引、Schema 或源内容。

## 第三组中等批次 700 / 600

- 同样 100,000 篇合成 RSS，首次全量构建 17.358 s；初次读取 5.865 s、聚类 5.490 s、代表项插入 2.367 s、成员插入 3.115 s、事务写入及发布 5.504 s。
- 第二次全量构建 17.402 s；读取 6.613 s、聚类 5.269 s、代表项插入 2.275 s、成员插入 2.775 s、事务写入及发布 5.056 s。前插、8 源并发、同源并发及旧代 GC 均通过，初次代表项 91,667，第二次 91,924；隔离环境退出码 0。
- 中等批次的首次事务写入 5.504 s，与 350/300 基线 5.515 s 基本相同；第二次 5.056 s 略低于基线 5.240 s，但属于单次短样本波动。当前没有可靠证据支持提升生产批次。

这些都是**独立容器中各一次的顺序测试**，首次 fetch 从 0.85 秒波动到 6.13 秒，说明不能根据总时长对算法作直接判断。代表项插入首次节约约 0.69 秒，但第二次反而慢 0.22 秒，成员插入无稳定改善。即便初次事务节约约 0.62 秒，也不足以支持增加生产的单次 SQL 参数体积与事务压力。

## 结论与上线门禁

当前不修改生产 350/300 默认参数。仅保留有边界的可选实验入口、单元测试和复测记录。完整 360k 在当前滚动哈希版本约 58–79 秒，写库仍约 28–34 秒。后续应在隔离副本上测试高效 COPY/批量插入替代方案，并在事务失败、WAL、锁竞争、峰值内存以及完整旧/新 generation 清理上做配对验证，而不是单纯扩大 ORM batch。仍不可将新的 Feed 去重投影用于生产。
