# Atoman 邮件平台完整实施计划（2026-11-06）

状态：分阶段实施；本文件严格区分已编码、已通过测试、生产验证及未实现项。邮件数据不因任务功能范围被扩大而允许跨账户访问。

## 范围、依赖与不可突破的约束

使用既有 Atoman Cookie/CSRF、Go 业务 API、Stalwart JMAP/IMAP/SMTP、PostgreSQL、私有 R2、独立发件 worker 和加密 NAS 备份。优先复用已有 PButton、PModal、PSheet、PSelect、PInput、PTextarea、PSearchInput、PDatetimePicker、PToastHost 和通知系统。禁止在浏览器保存管理员凭据、原始 IMAP 密码、未经同意外传邮件正文、在未知发件状态重复提交。图书、音乐、其他后台功能及脏工作区必须保持不变。

## A. 可靠性与投递（P0：尚有真实生产验收缺口）

1. Gmail 垃圾邮件诊断：保留原始 MIME，逐封核验 SPF、RSA/Ed25519 DKIM、DMARC、MX、PTR、EHLO、TLS、SMTP 重试、退信和认证头；交叉使用 Google Postmaster Tools、真实 Gmail/Outlook/其他邮箱投递记录。此前两封 Gmail SPAM 的认证为 pass，不能无证据认定根因，也不能将测试邮箱加白名单作为修复。只在有证据时评估发件信誉与第三方 SMTP 中继。验收：多个自然日、多个供应商正常邮件实际到达 INBOX，退信可追踪。
2. 外部故障告警：在已有 systemd/journal、30 分钟健康检查基础上，监控 Stalwart、后端、outbox、队列超时、证书、R2 对象、隔离备份、NAS；用户指定独立外部 webhook/电话/收件人并完成真实断服务和收敛测试后再启用。当前只有本机 journal，没有可验证的外部告警通道；不得宣称已开通。
3. 灾难恢复：完整备份三库、邮件对象、证书及原密钥，保留 15 天且至少两份；纳入新增 mail_contacts。现有 mail_* 动态表选择可以捕获通讯录，但必须进行新增表的同源源备份与 NAS 隔离恢复才算完成。历史全站加密包向 NAS 传输缓慢、全站完整恢复证据缺失，不能以邮件胶囊恢复成功替代全站完成。

## B. 基础体验（P1：当前开发分支已实现候选）

1. 全站未读：按登录用户身份提供 Inbox 未读数及最新邮件 ID；顶部邮件按钮、手机模块目录显示 99+ 上限；45 秒刷新且切回前台补刷；只有新消息 ID 与未读增量同时变化才显示 Toast，用户手动改未读不误报。登出、切换用户或 401 时不可展示旧账号数。用户可控制本设备提醒，浏览器通知需主动授权。
2. 私人通讯录：用户 UUID 约束，姓名、地址、备注用既有每记录 AES-GCM vault 加密；最多 500 条，唯一邮箱、防重复、防并发覆盖 revision、增删改查，To/Cc/Bcc 独立建议，只有明确选择才插入。禁止自动从密送或历史邮件收集联系人。测试包含密文中无明文、跨账号 404、版本冲突。
3. 自动签名：现有加密 MailPreference 扩展 enabled、text、html、on_reply；服务端清理危险 HTML，前端再次过滤。仅对未编辑、未保存的新草稿添加一次，回复控制独立。不得污染历史草稿。

## C. 效率（P2：当前开发分支已实现候选）

1. 高级搜索：通过用户自身 JMAP Email/query，组合发件人、收件人、主题、正文、日期、已读、星标、附件；当前文件夹或全部文件夹。输入长度、控制字符、日期区间和服务端账户范围验证；分页由服务端执行；空结果与清除筛选一致。
2. 定时发送：加密草稿保存 send_at，服务器拒绝小于 5 秒或超过 90 天的计划；持久 outbox 在邮件快照写入成功后重新计算不小于 5 秒撤销窗口；独立 worker 到期单次 claim，取消后绝不发送，未知发送结果不盲重试。已排期任务在重开页面后可查询并取消。要验证重启、长延迟上传、幂等、服务器时区、失效时间。
3. 安全附件预览：仅按文件头识别 PNG/JPEG/GIF/WebP 与 PDF；图片 object URL 离开页面销毁，PDF 复用图书模块 pdf.js worker 渲染 canvas，限制大小、页数和像素。SVG、HTML、脚本、Office 或未知格式只能下载，永不在本站来源内执行。
4. 快捷键：C 写信、J/K 上下会话、R 回复、E 归档、S 星标、斜杠聚焦搜索、问号帮助、Esc 返回；输入框、编辑器、写信抽屉及弹窗内禁用全局拦截，避免误操作。

## D. 多邮箱与外部迁移（P3：当前未实施，必须独立安全门槛）

1. 现有邮箱账户与 Atoman 用户是一对一映射，不能仅做前端下拉框。需先设计新的每用户多外部账号与加密连接凭据库，服务端隔离的 OAuth/IMAP/SMTP 授权、独立唯一索引、TLS 身份校验、内网/本地地址拒绝的 SSRF 防护、账号级限流和按来源映射文件夹。
2. 迁移时按 UIDVALIDITY/UID 和内容指纹双重去重，持久化任务状态、幂等键、进度、暂停、取消、断线恢复、恢复后的再次校验；支持文件夹/附件/日期/已读/Message-ID 信息保留，不把密文外部密码写入日志。建议先镜像到 Stalwart 每来源文件夹，再考虑跨服务实时操作。
3. 未通过多用户越权、密钥吊销、SSRF、真实 IMAP TLS、连续同步、备份 NAS 恢复与独立 SMTP 退信/投递验证，不得激活真实外部账号收发。需要用户主动授权实际外部提供商连接。

## E. AI 邮件辅助（P3：当前未实施，需模型服务与用户显式授权）

1. 摘要、自动分类建议、回复草稿均默认关闭、按用户逐项开启；仅返回供用户修改的建议，不触发发送或已读修改。
2. 请求必须明确告知 AI 提供商、数据范围、费用、保留政策与可删除方式，不把任何邮件自动提交给未选择的第三方模型。限制长度、危险链接和附件，模型输出不可信、不得执行邮件中的提示注入。
3. 实施前需明确用户认可的模型服务与私有数据处理协议；实际 API 费用/外联配置、注入防御、越权测试通过方可启用，不能用规则模板冒充 AI。

## F. 提交、生产部署与回滚门槛

1. 任务分支测试：Go 邮件/迁移/应用路由测试，go build 全部目标；前端 type-check、用户文案、组件单元测试；真实 Chrome 模拟邮箱（不发送真实邮件）覆盖高级筛选、联系人建议、签名、定时取消、附件安全、桌面三栏和 320/390px 手机不溢出。
2. 生产数据库在新版本生效前，用 mail_admin 的 migrate-mail 操作迁移新增 mail_contacts，验证索引/用户关联/权限，不执行无关业务迁移。新 schema 应参与后续新源备份和 NAS 隔离恢复。
3. Go 发布须同源包含 start_server、music_import_worker、mail_outbox_worker、mail_maintenance_worker、mail_admin 五个二进制。使用官方不可变发布路径和已有回滚脚本；不允许 current 软链接缺少邮件 worker。先验证数据库迁移、运行时环境、备份与全链路生产 readyz，然后切换并监测。
4. 前端 GitHub main 与 Cloudflare Pages production 部署 commit 必须一致。确认 /mail HTTP 200、登录后真实读写、联系人数据、签名、搜索、队列、附件不影响原有邮件，并保留所有历史邮件原始 MIME。
5. 交付状态严格分别写出：代码完成、自动测试通过、模拟浏览器通过、真实生产通过以及尚未完成；不得将 D/E 蓝图、Gmail SPAM 或慢速 NAS 全站传输写作已解决。

## 当前关键验收事实

- 之前已上线基础 Webmail，真实双向收发、完整邮件胶囊 NAS 隔离恢复曾通过；历史外发 Gmail SPAM 两封、全站 NAS 大包和客户端代理问题仍有独立缺口。
- 本分支新增 P1/P2 API、界面、加密联系人、签名、定时队列、高级搜索和附件安全预览；在生产发布前标为候选，不能声称已切换生产。
- D/E、外部告警投递及 Gmail INBOX 稳定投递尚未真实完成。完成这些项目必须另做真实凭据/供应商/外部链路验收，不能仅凭合成测试宣称全功能上线。
