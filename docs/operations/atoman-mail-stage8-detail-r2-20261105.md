# Atoman Mail Stage 8 — safe plaintext detail, expand-only read, existing R2 access probe

- Atoman backend `GET /api/v1/mail/message?mailbox_id=<id>&message_id=<id>` checks existing Atoman session, active local mailbox mapping, per-user encrypted JMAP key, matching Stalwart session account and that the requested JMAP message belongs to the selected folder. The response includes bounded plain text (64 KiB), parsed sender/recipient/cc, attachment metadata and read state. It never returns HTML, raw blobs or JMAP auth keys.
- A separate authenticated `POST /api/v1/mail/messages/read` with JSON `{ "mailbox_id": "...", "message_id": "..." }` checks the same scope and applies `Email/set` patch `keywords/$seen: true` only after the UI has actually rendered a selected message. Listing messages, searching the list and opening folders do not mark items read. Stale requests cannot replace newer selections.
- Vue Webmail shows escaped pure text, not HTML. The attachment list is metadata-only, no fake download links. The frontend refuses to claim full HTML or downloads, and does not enable the live page for reserved users.
- A real disposable Stalwart v1 + PostgreSQL + MinIO S3 fixture accepted local synthetic SMTP, exposed its text body through JMAP, updated `$seen` and confirmed the state on a subsequent JMAP read. Data was isolated from production and test containers were cleaned.
- `ProbePrivateMailObjects` is an opt-in synthetic object test over **existing** Atoman S3 credentials. For each private mail bucket it writes one random, reserved-prefix probe object, reads and SHA-256 verifies its bytes, deletes it and checks for 404. It never touches the existing `atoman` public bucket, modifies bucket ACLs, lists real messages or creates a credential. It attempts to clean up synthetic objects even if a step fails.
- The probe is deliberately **not run** on production by default and there is no new mail R2 token. To run in an operator-authorized secure process where existing `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` are already supplied by the normal runtime: `ATOMAN_MAIL_R2_RW_INTEGRATION=1 go test ./internal/modules/mail -run '^TestLiveExistingMailR2ObjectsOnlyWithExplicitOperatorOptIn$' -count=1 -v`. Never print or scrape another process's environment, or commit credentials. Public R2 access still disabled.

Release gates remain closed: actual R2 read/write, complete PG+R2/TrueNAS restoration, production Stalwart provisioning, and SMTP/DNS cutover preserving existing `support@atoman.org` forwarding. Do not set `ATOMAN_MAIL_READ_ENABLED=1` or change MX merely because these read and probe adapters pass isolated tests.
