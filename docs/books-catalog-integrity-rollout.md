# 图书目录第一阶段：上线前检查与发布顺序

**状态：开发分支内实现，尚未部署。** 不运行本文件中的任何修复 SQL；先保留数据库备份与审计结果。

## 基线（2026-11-03，生产库只读审计）

- 2 个作品、1 个版本、2 个作者、2 条贡献关系、2 个新版电子书资源。
- 1 个 active 版本语言、ISBN、出版社、版次均为空；上线后应通过书目核实修复，不得随机填入。
- 4 条 `book_sources` 的 `target_type=work, kind=direct_upload` 引用不存在的作品；需查明历史数据来源。
- 1 个 EPUB `book_assets` 无 current revision，也无上传会话；公开读取接口当前会过滤未就绪文件。
- 当前贡献关系、作品→版本、资源→版本关联抽查均没有断链或重复关系。

## 代码变更范围

1. `CreateBookWork` / `CreateBookEdition` 与 Wiki 版本编辑使用统一验证；作者同名需显式复用已有 ID 或确认新建。
2. 新增只读的疑似重复候选接口，**不会自动合并作品或版本**。
3. 支持带 `Idempotency-Key` 的作品与版本创建；同键相同请求回放创建结果，复用不同请求报冲突。
4. 新增独立的 `book_catalog_create_receipts`，仅保存请求摘要与目标 ID，不重复保存作品正文。
5. 新迁移为贡献关系补部分唯一索引与可延迟外键，便于 Wiki 合并和撤销的事务操作。

## 数据库迁移注意事项

- 迁移中的 `NOT VALID` 只跳过历史数据验证；它依然限制**新插入与被更新**的记录。
- 生产当前已有 1 条不完整 active 版本，因此上线前应确认 Wiki 界面能一次补齐语言与版本身份，或先单独验证修复路径。**不要自动猜测资料。**
- 上线之前检查 `book_contributions` 现有重复组；部分唯一索引在历史有重复的情况下会失败，不能在启动失败后盲目反复运行。
- 与 `book_sources` 相关的 4 条历史悬空数据不能机械删除；本期不为多态目标增加外键。
- 对于 1 个无可读修订的 EPUB，不推断其状态或主动下架，先分析是否是未完成的上传。

## 上线顺序（需单独审批）

1. 先执行 **只读数据库预检查**，确认异常数据数目及迁移前提；备份生产库并验证备份可读。
2. 在隔离 PostgreSQL 上完成 catalog、Wiki 合并/撤销、阅读与 API 回归。
3. 检查前端类型检查、创建页面的作者复用/重复确认/上传关联流程。
4. 经明确同意后发布后端与数据库迁移，再发布前端，执行非破坏性 smoke check。
5. 监控新建冲突率和版本校验错误，并复核原有作品/版本访问是否正常。

## 回滚原则

- 撤销代码不应删除 `book_catalog_create_receipts` 或历史资料。
- 新增的数据库约束可能与旧版允许空语言的写入行为不兼容，因此**不能只回滚程序而忽略数据库约束**。如果必须恢复旧版服务，应先评估受影响写入，再制定独立的约束回退方案。
- 不在自动迁移或发布脚本里执行数据合并、重写、批量删除或手工补全。
