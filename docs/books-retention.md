# 书籍授权证据保留策略

当前采用 B 策略：

- 授权证据对象和申诉材料在最终决定后保留 2 年。
- 审核日志至少保留 7 年。现有 `audit_logs` 是 append-only，不执行删除，因此实际保留时间可以超过 7 年。
- 待审申诉会阻止对应申请的证据和申诉材料清理。
- 审核人员可以对申请设置或解除法律保全。保全期间不会清理对应材料；设置和解除操作会写入审核日志。

## 清理行为

书籍 worker 启动时执行一次保留期巡检，之后每天执行一次。清理前会重新锁定申请并检查：

- 申请必须已经完成最终审核；
- 申请不能处于法律保全状态；
- 申请不能存在待审申诉；
- 申请最终决定时间（包括最后一次已处理申诉决定）必须早于当前时间两年。

满足条件后，worker 删除私有 R2 授权证据对象，清空数据库中的对象 key、文件名、类型和大小，并删除已完成的申诉材料。清理失败时保留数据库记录，下一次巡检会重试；清理动作本身会写入不可删除的 `books.retention.cleanup` 审核日志。

## 法律保全接口

审核人员使用以下接口管理保全状态：

```text
POST /api/v1/books/review/publication-requests/{requestId}/retention-hold
```

请求体：

```json
{"held": true, "reason": "legal preservation request"}
```

解除保全时将 `held` 设置为 `false`，并提供解除理由。设置和解除都要求 `books.review` 权限，且理由不能为空。

## 运营注意事项

R2 bucket 生命周期规则不应直接删除 `books/private/publication-evidence/` 下的对象。应用 worker 需要先完成数据库条件检查、对象删除和审计记录，确保待审申诉与法律保全不会被绕过。R2 生命周期可以作为孤立对象的后备清理，但应使用单独的隔离规则并避开未到期对象。
