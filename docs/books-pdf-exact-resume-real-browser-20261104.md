# Fixed-revision book reader: precise PDF resume + real Chrome validation (2026-11-04)

## Implemented

- Cloud PDF reading state includes `pdf_page` and normalized `pdf_offset` within that page, independent of zoom, alongside `current_percent` and `furthest_percent`.
- Additive `pdf_offset` DB column: default 0, non-null, check [0,1]. Older clients omit the field and default to zero. Reject nonzero PDF offset on EPUB, TXT, CBZ and CBR.
- Cloud states stay isolated by user and immutable revision, with version/conflict and idempotency safeguards. Deliberate jumps and reflow send `advance_furthest=false`.
- PDF.js native continuous reader observes movement within one page as well as page changes; restores PDF exact fraction after reload. Paginated reader still available.
- Local anonymous reading progress also stores page and offset, retaining compatibility with legacy percentage-only caches.
- EPUB.js continuous view additionally watches manager scrolling, since wheel events inside iframes do not bubble to the outer component.

## Verification

- Original offline fixtures: 12-page PDF, five-chapter EPUB, generated by `Atoman-Frontend/scripts/gen-book-reader-fixtures.py`.
- Playwright real Chrome: `playwright.books-reader.config.ts`, `tests/e2e-smoke/book-reader-real.spec.ts`, with mock HTTP metadata and real PDF.js / EPUB.js in an isolated local Vite development server.
- Scenarios: PDF multi-page rendering, scroll offset, reload position, paginated mode; EPUB chapter loading and mode reflow. Backend tests for format validation, cloud state and per-revision isolation.
- Zero production DB writes, object storage upload, remote push or deploy.

## Remaining

- PDF bookmark within-page anchors currently remain page-only. User progress within page is precise.
- Legacy imported/private-book reader is separate and needs parity work; mobile multi-touch verification remains open.
