# Papers AI Agent: reviewed cross-file plans and temporary conversation

This release extends the owner-controlled AI suggestion endpoint without a database migration.

- A request can include up to six complete, explicitly previewed previous dialogue turns, with a combined maximum of 16 KiB. History is reference data, not instructions or proof of accepted edits. The browser holds history only in the open file panel and clears it on scope/provider configuration changes or closure. Nothing is stored in browser storage or the database.
- The project task requires the saved project head revision and the complete saved active file. At most four other explicitly selected and previewed saved text files may be attached. The model may return one exact contiguous before/after replacement per supplied file, up to five files. Missing, ambiguous, duplicate, or unauthorized replacements invalidate the entire plan. The server attaches trusted file IDs and revisions after validation and rejects a project change during the model call.
- The frontend independently validates the exact replacement against the captured source. Nothing is written during generation. No proposal is selected by default. The owner selects changes and confirms the existing atomic replace_text operation. Project and file revision checks make the operation all-or-nothing; the previous versions remain in existing file history. A lost response is not automatically retried.
- Batch application is limited to ordinary editing, with clean saved source. A normal structural file write can invalidate other participants' existing CRDT epochs; the UI warns the owner to coordinate. Single-file reviewed AI edits remain supported in the existing CRDT workflow.
- Existing outbound HTTPS restrictions, consent, rate limits and credential handling remain in force. No API keys in prompts, history or returned edits. Provider output is untrusted and never executed. No autonomous tool use or automatic compile-repair loop in this release.
