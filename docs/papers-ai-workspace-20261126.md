# Papers AI task workspace and contributor

- The fixed server-issued contributor descriptor is an attribution principal ("papers-agent", "Papers Agent", "ai", "propose_only"), never an account, member role, session, credential, or autonomous writer. Server activity distinguishes owner request, AI proposal, incomplete request, owner-approved commit and owner-approved rollback. The file version author remains the authenticated human owner.
- The owner-only historical changes endpoint binds one committed/rolled-back event and one affected file to immutable before/after revisions. It verifies both hashes against the original audit metadata, respects file deletion and checks current invitation and ownership in the same transaction. It does not return uncommitted provider output or read other files. No additional manuscript copies are stored.
- The workbench groups the latest fifty audit events by attempt, shows live approval only for the proposal held in the current file's in-memory panel, and labels old proposals as generated without a recorded commit. It displays the contiguous changed range in the current proposal or on-demand verified historical diff; this is not a claim of fine-grained line attribution. Expand/collapse changes layout without remounting the editor.
- Keys and dialogue remain scoped to the open file panel. The AI participant is not a separate CRDT peer. Single-file local/CRDT accepted edits are still ordinary human edits, not server-attested AI commits.
- No migration, new access grant, automated write capability, or additional provider request is introduced.
